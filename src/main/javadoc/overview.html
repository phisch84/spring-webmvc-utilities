Spring MVC Web Application Utilities 2: the application layer between Spring MVC controllers and the repositories of the {@code domain-repository3} library. It converts entities to data transfer objects (DTOs) and back, and it executes handlers for custom annotations of controllers.

Where to start

  • Exchanging entities with clients: {@link com.schoste.ddd.application.v2.dtos.DataTransferObject} and {@link com.schoste.ddd.application.v2.dtos.DataTransferObjectConverter}.
  • Writing a converter: {@link com.schoste.ddd.application.v2.dtos.standard.DataTransferObjectConverterImpl}; the package {@link com.schoste.ddd.application.v2.dtos.standard} shows a complete example.
  • Handling custom annotations: {@link com.schoste.ddd.application.v2.interceptor.AnnotationInterceptor} and the handler base classes; the package {@link com.schoste.ddd.application.v2.interceptor} shows a complete example.
  • Exceptions: {@link com.schoste.ddd.application.v2.exceptions}.

Rules in brief

  • A DTO refers to its entity by id. A null or virtual id means a new entity; an actual id means the repository's entity with this id, and if there is none, {@link com.schoste.ddd.application.v2.exceptions.EntityNotFoundException} is thrown.
  • Converting never changes the id of a DTO or assigns it to an entity: entity ids are managed by the repository.
  • Converting never adds an entity to its repository or saves it; that's up to the caller and a Unit of Work.
  • Properties are converted automatically by the setters annotated with {@link com.schoste.ddd.domain.v3.annotations.AutoSet}; the rest is done in hooks of the converter.
  • Converters and annotation handlers are Spring beans. A project adds its own annotations by writing handlers which extend a handler base class with the annotation as type argument; an annotation may have several pre and post handlers. Annotations without handlers are ignored, requests of static resources pass unhandled, and configuration errors (an unresolvable handler, an interceptor without application context) fail with an {@link java.lang.IllegalStateException}.

Common mistakes

  • Expecting a conversion to save: converting only converts; add the entity (new) or mark it modified (existing) in the repository and commit a Unit of Work.
  • Making up actual ids on the client: an id the repository doesn't know throws {@link com.schoste.ddd.application.v2.exceptions.EntityNotFoundException}; new objects have a null or virtual id.
  • Forgetting {@code @AutoSet}: properties whose destination setter isn't annotated aren't converted; set them in the converter's {@code afterAutoConversion} hooks.
  • Leaving the handler's type argument open (e.g. a generic handler class), or creating the interceptor with {@code new} instead of by Spring: requests fail with an {@link java.lang.IllegalStateException}.
  • An annotation without runtime retention: its handlers never run.

Getting the artifact

The artifact {@code com.schoste.ddd.application:spring-webmvc-utilities2} is published to GitHub Packages, together with this Javadoc ({@code javadoc} classifier); it brings {@code domain-repository3} and {@code dao4} along, which come from the registries of their own repositories. Release versions end with {@code .RELEASE}. The README of the GitHub repository shows the Maven settings and the changelog.

Compatibility

Compiled for Java 8. Needs Spring 5.3 and Servlet 4.0 ({@code javax.servlet}), which the web application provides. The major version is part of the artifact id ({@code spring-webmvc-utilities2}) and of the package name ({@code com.schoste.ddd.application.v2}).
